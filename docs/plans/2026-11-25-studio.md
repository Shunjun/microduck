# Studio implementation plan

Approved design: companion UI, matching `studio-v5-full-height-pages-d941.html`.

- [x] Serve the approved shell with five pages, full-height footer, viewport-sized control preview and dismissible companion notice. Autonomous page is an entry only.
- [x] Retain robotd as sole hardware owner. Add a same-origin, bounded WebSocket bridge for live joint state and continuous joystick commands; retain servo-debug RPC.
- [x] Add a local action library: both ONNX and editable manifest required, bounded uploads, validation through existing policy loader, atomic storage. No automatic activation. Installed skills remain managed by robotd.
- [x] Connect real telemetry, existing skills and explicit policy assignment. Preserve debug, standard-pose zero capture and independent body IMU calibration. Put persistent joint settings on configuration page.
- [x] Verify manifest validation, storage/path boundaries, WebSocket permissions/lifecycle, existing debug behavior, JS syntax, Rust checks, and layout with a debug browser where available. Update mechanism documentation.

Files: `studio/src/{lib,rpc,session,library}.rs` HTTP/storage/IPC; `studio/web/{app,state,control,actions,debug,ui}.js` separate page responsibilities, `debug.html` retained debug markup, `style.css` shared theme/frame, `control.css`, `actions.css`, `debug.css` page styles. `preview.js` remains the full CAD renderer. Service receives a writable StateDirectory; deployment remains explicit.

Unknown values must stay unknown, never zero or sample data. Browsing/importing never powers motors. A closed or inactive control session releases its movement intent; a global stop is always explicit. A model validation failure leaves no installed library entry. Settings and model storage are separate from `/etc/robot/feetech1910.json` and robotd owns all servo calibration writes.


## Additional approved hardware scope

Replace the entry-point motor constant with `[bus].driver = "xl330" | "feetech1910"`. Default remains Feetech. robotd owns configuration persistence and reports active versus configured drivers; no live protocol switching. Studio exposes it under configuration/hardware. API 70 requires deploying Studio and robotd together. Startup, init, normal bus and IMU checks consume the chosen configuration. XL330 commissioning/debug is explicitly unsupported rather than falling through to Feetech.

No physical servo, camera, model inference or deployment validation has been performed.
